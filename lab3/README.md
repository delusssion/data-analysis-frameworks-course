# Лабораторная работа №3

## Изображения и видео

## Цель

Извлечь готовую разметку объектов («украсть разметку») из видео `output.mp4`, на котором уже нарисованы bounding box'ы, преобразовать её в формат COCO, оценить качество извлечения по IoU относительно эталонной CVAT-разметки и обучить детектор объектов на основе `torchvision.models.detection`, оценив его по mAP.

## Что сделано в работе

В ноутбуке выполнены основные этапы работы:

1. Декодированы оба видео (`input.mp4` без разметки и `output.mp4` с нарисованными bbox), извлечены метаданные (FPS, число кадров, разрешение, длительность), кадры сохранены на диск.
2. Реализованы и сравнены три способа автоматического извлечения bbox из `output.mp4` методами OpenCV:
   - разница кадров (`absdiff` + threshold + морфология),
   - Canny по разности кадров,
   - HSV-фильтрация по цвету рамок с автоматическим подбором гистограммы.
3. Для каждого способа собраны bbox в формате `{frame_id: [[x1, y1, x2, y2], ...]}`, отфильтрован шум, объединены пересекающиеся прямоугольники.
4. Эталонная разметка прочитана из `annotations.xml` (CVAT 1.1, треки с интерполяцией) — она используется только для оценки качества по IoU. Реализованы `iou()`, жадное сопоставление по максимальному IoU при пороге 0.5, метрики mean IoU / precision / recall / F1 / TP / FP / FN, выведена сравнительная таблица.
5. На основе лучшего по F1 метода построен COCO-датасет (один класс `vehicle`), сохранены `coco_full.json`, `coco_train.json`, `coco_val.json`, `coco_test.json` с хронологическим разбиением 70/15/15 (соседние кадры почти одинаковые, поэтому случайный split дал бы оптический leak).
6. Написан `CocoVehicleDataset` (PyTorch), который читает COCO JSON и возвращает таргеты в формате torchvision detection (`boxes`, `labels`, `image_id`, `area`, `iscrowd`).
7. Дообучен `fasterrcnn_mobilenet_v3_large_fpn` с pretrained-весами: голова заменена под 2 класса (background + vehicle), используется early stopping по validation mAP, лучший чекпоинт сохраняется в `models/best_model.pth`. Построены графики train loss и val mAP по эпохам.
8. На тестовой выборке посчитаны `mAP`, `mAP@0.5`, `mAP@0.75` через `torchmetrics.detection.MeanAveragePrecision`; результаты сведены в таблицу с обсуждением ошибок.
9. Сделаны визуализации (удачные и провальные кадры извлечения, предсказания модели рядом с GT) и собраны два видео:
   - `videos/extracted_annotations.mp4` — `input.mp4` с моей извлечённой разметкой;
   - `videos/model_predictions.mp4` — `input.mp4` с предсказаниями обученной модели.
10. В финальном выводе обсуждены ограничения метода (склейка соседних bbox, потеря тонких рамок, единый класс `vehicle`, наследование шумов разметки моделью) и возможные улучшения.

## Установка зависимостей

### Вариант 1: через `pip`

```bash
cd lab3
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
```

Если нужен отдельный kernel для Jupyter:

```bash
python -m ipykernel install --user --name video-detection-lab3
```

### Вариант 2: через `uv`

```bash
cd lab3
uv venv
uv sync
```

Если нужен отдельный kernel для Jupyter:

```bash
uv run python -m ipykernel install --user --name video-detection-lab3
```

## Данные

Исходные файлы лежат в [data/](./data):

- `input.mp4` — видео без разметки;
- `output.mp4` — то же видео, но с уже нарисованными bbox;
- `annotations.xml` — эталонная разметка в формате CVAT 1.1 (используется только для оценки качества).

Если файлов нет локально, ноутбук попытается скачать `input.mp4` и `output.mp4` через `gdown` по ссылкам Google Drive из условия задания.
